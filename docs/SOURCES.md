# Primary references and attribution

Checked 18–19 October 2026. The application and telemetry protocol are original project code. Manufacturer facts and CLI behavior were checked against the sources below; current installed-tool behavior still needs validation on the equipment. No Nuand/ST implementation code was copied into the repository.

- [Nuand bladeRF repository](https://github.com/Nuand/bladeRF): upstream host libraries, firmware/FPGA support, and release context. Keep this external dependency's license separate from this project's original code.
- [Nuand bladeRF xA9 product page](https://www.nuand.com/product/bladerf-xa9/): identifies the 2.0 micro xA9, AD9361, 2×2 architecture, and Cyclone V platform. Custom FPGA accelerators are an extension opportunity; this project does not implement one.
- [Nuand basic device verification](https://github.com/Nuand/bladeRF/wiki/Getting-Started:-Verifying-Basic-Device-Operation): identity/configuration checks, stream concepts, attenuation/loading guidance, and the xA9 `rfic_bist` digital-loopback boundary. Some examples on this page refer to older board families; do not copy their gain stages blindly.
- [Nuand CLI tips](https://github.com/Nuand/bladeRF/wiki/bladeRF-CLI-Tips-and-Tricks): finite RX recording, the need to wait for completion, raw SC16Q11 interpretation, and shell scripting examples. Our adapter uses subprocess argument arrays and fixed local capture filenames rather than shell execution.
- [Nuand CLI command handling](https://github.com/Nuand/bladeRF/blob/master/host/utilities/bladeRF-cli/src/main.c): confirms repeated `-e` arguments are executed in order. [Configuration implementation](https://github.com/Nuand/bladeRF/blob/master/host/utilities/bladeRF-cli/src/cmd/printset_impl.c) and [RX implementation](https://github.com/Nuand/bladeRF/blob/master/host/utilities/bladeRF-cli/src/cmd/rx.c) were consulted for channel-specific gain/AGC/readback and finite RX channel selection. The adapter still requires live CLI-version verification.
- [Pinned Nuand interactive CLI reference](https://github.com/Nuand/bladeRF/blob/35174c30b009cdb335800c411f3c14d45283f12b/host/utilities/bladeRF-cli/src/cmd/doc/interactive-help.md): v0.3 audit at upstream commit `35174c30b009cdb335800c411f3c14d45283f12b`, dated 20 August 2026. A positive RX `n` is finite; TX `repeat=1` offers the file once, while zero repeats indefinitely. The application uses a finite one-file TX burst only.
- [Pinned Nuand RX lifecycle](https://github.com/Nuand/bladeRF/blob/35174c30b009cdb335800c411f3c14d45283f12b/host/utilities/bladeRF-cli/src/cmd/rx.c) and [shared RX/TX worker](https://github.com/Nuand/bladeRF/blob/35174c30b009cdb335800c411f3c14d45283f12b/host/utilities/bladeRF-cli/src/cmd/rxtx.c): starting a task is not a sample-arrival guarantee, stopping is asynchronous, and a timed wait can return while a task remains running. The adapter therefore checks stream state, errors, received-byte readiness and finite file length rather than trusting one command acknowledgment.
- [Pinned Nuand TX lifecycle](https://github.com/Nuand/bladeRF/blob/35174c30b009cdb335800c411f3c14d45283f12b/host/utilities/bladeRF-cli/src/cmd/tx.c), [CLI shutdown/signal handling](https://github.com/Nuand/bladeRF/blob/35174c30b009cdb335800c411f3c14d45283f12b/host/utilities/bladeRF-cli/src/common.c), and [echo command](https://github.com/Nuand/bladeRF/blob/35174c30b009cdb335800c411f3c14d45283f12b/host/utilities/bladeRF-cli/src/cmd/cmd.c): normal TX teardown differs from host process termination. The finite adapter uses unique echo acknowledgments and explicit cleanup state checks; forced termination retains unconfirmed cleanup. [The adapter audit](BLADERF-DUPLEX.md) gives line-level references and test scope.
- [GNU coreutils `stdbuf`](https://www.gnu.org/software/coreutils/manual/html_node/stdbuf-invocation.html): line buffering for the Linux interactive CLI's piped output; this is an external runtime dependency of physical duplex, not a hardware timing guarantee.
- [Nuand bladeRF2 gain definitions](https://github.com/Nuand/bladeRF/blob/35174c30b009cdb335800c411f3c14d45283f12b/fpga_common/include/bladerf2_common.h): overall TX channel gain and TX DSA attenuation have different references and ranges. The finite controller uses overall `set gain tx1`, with a conservative integer project range of -23 through 0 dB and default -20 dB; it does not treat these values as dBm.
- [SciPy `resample_poly`](https://docs.scipy.org/doc/scipy/reference/generated/scipy.signal.resample_poly.html): the explicit rational sample-rate conversion used for prepared quantized bursts and compatible RX processing. The resampling ratio and actual sample rates remain in saved metadata.
- [ST NUCLEO-F446RE product page](https://www.st.com/en/evaluation-tools/nucleo-f446re.html): board identity and supported development ecosystem.
- [ST UM1724, Nucleo-64 MB1136 manual](https://www.st.com/resource/en/user_manual/um1724-stm32-nucleo64-boards-mb1136-stmicroelectronics.pdf): board layout, debugger/virtual COM functions, USART routing, power configuration, and solder bridges. Inspect the revision of the actual board before applying routing instructions.
- [Python zlib CRC32 documentation](https://docs.python.org/3/library/zlib.html#zlib.crc32): Python reference CRC behavior used by the telemetry codec. This checksum detects accidental corruption and is not an authentication mechanism.
- [Qt for Python](https://doc.qt.io/qtforpython-6/): native PySide6 application framework. Native GUI QA used the project's actual widgets on Qt's offscreen platform.
- [scikit-learn grouped evaluation](https://scikit-learn.org/stable/modules/cross_validation.html#cross-validation-iterators-for-grouped-data): why observations sharing a group belong together when measuring generalization. The project uses explicit whole-session split manifests.

The teaching examples use dimensional analysis and controlled simulated experiments. They are not 3GPP conformance tests, calibrated RF measurements, or a certification curriculum.
